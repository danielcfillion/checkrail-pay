Tasks only Daniel can do: they need a personal login, a signature, a payment method, a phone or a face. The AI builder lane works on everything else in parallel. Work the queue top to bottom. When a task is done, change its status and paste what it says to return into the chat so the builder lane can continue.

Status values: Not started, In progress, Done, Blocked.

## Notes

- The single highest-value minute in the whole project: obligation 3 paying through the real PayPal sandbox (H1) with the payout batch id visible in the sandbox dashboard. Two judges' worth of score depends on it. Do H1 first.
- PayPal Payouts on a live (non-sandbox) account is an approved feature for business accounts and may not be available to Vietnam-registered senders. The hackathon only needs the sandbox. Do not apply for live Payouts until an entity that can own it is decided.
- Before any real money: set `DUELINE_BASIC_AUTH=user:pass` (or put the app behind a proxy that authenticates), use a separate read-only PayPal app for the agent's tools, and read the "Not done" list in the README Honesty section (fee-bump handling, SEP-29 memo checks, anchor path payment).
- If a Stellar attempt shows status unknown, do not retry blindly. Check the treasury account on a block explorer first; the app refuses a second payment while an earlier attempt is unresolved.

- H1, H2 and H3 can be done in any order and should all be done on Monday.
- H4 depends on nothing but is worth more once H1 is done, so both rails show live in the same replay.
- H6 is the only task that benefits from everything else being done first. If time runs short, record in mock mode and say so on screen; the sidebar footer already shows the mode.
- Keep every secret in `.env` only. The repo ignores `.env*`. Never paste a secret into chat, a doc or a commit message.
